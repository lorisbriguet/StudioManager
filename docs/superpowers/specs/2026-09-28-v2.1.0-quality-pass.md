# v2.1.0 Quality Pass — Design

**Date:** 2026-09-28
**Status:** approved in conversation, pending written review
**Ships in:** v2.1.0, alongside the already-merged demo build and guide work

## 1. Goal

Clear the backlog that has accumulated around the 2.0 releases, in three piles: keyboard navigation parity, seven small correctness defects, and the structural debt in the largest files. Nothing here changes what the app does for the user, except where a defect is fixed.

## 2. Non-goals

- **The invoice and quote forms stay separate.** Their overlap is structural, not behavioural: the invoice carries currency and exchange rates, contacts, purchase orders, a delete flow and quote conversion; the quote carries task import and its own validity rule. A shared form behind a mode flag would hide those differences rather than remove them, on the two screens that matter most and have the thinnest coverage.
- No visual redesign, no new features, no schema changes beyond three indexes.
- **No generated document may change.** The PDF work is a pure reorganisation; invoices and quotes must render exactly as they do today, to the byte where react-pdf is deterministic.

## 3. Part A — Arrow-key navigation parity

`useListNavigation` (already used by Invoices, Quotes, Expenses, Income) gains three more callers. Behaviour is the hook's existing contract: Up and Down move a visible focus ring, Enter opens the row, Space opens its context menu at the row's position, and the hook stays inert while the user types or a menu or dialog is open.

- **Clients** (`src/pages/ClientsPage.tsx`): a table like Invoices. Items are the visible sorted rows, `onOpen` navigates to the client, `onMenu` opens the existing row context menu. Rows get `data-list-row` and the focus ring.
- **Projects** (`src/pages/ProjectsPage.tsx`): a card grid, not a table. Navigation runs over the cards in visual order, one card per step, which is what the eye follows in a single-flow grid. Left and Right are not bound, so horizontal arrows keep their default behaviour.
- **Tasks** (`src/pages/TasksPage.tsx`): tasks are grouped by project and groups can be collapsed. Navigation runs over the visible task rows only, in render order, skipping the tasks of collapsed projects. The page already computes a flattened list; the navigable list is that list filtered by the collapsed set. Group headers and subtask rows are not navigation stops in this pass.

Each page keeps its existing mouse behaviour unchanged.

## 4. Part B — Correctness fixes

1. **Double-submit on client create** (`src/pages/ClientsPage.tsx`): the quick-create form's save can be pressed repeatedly while the mutation is in flight, creating duplicates. Disable it while pending, and do the same for the other create paths that lack it: the Tasks page Enter-to-create and the new wiki article button.
2. **Wiki autosave writes to a stale article** (`src/pages/WikiPage.tsx`): the debounced save captures the article id when it is scheduled. Switching articles inside the two-second window can land the save on the wrong record. Check the current article id when the timer fires, drop the write when it no longer matches, and surface a failed save instead of swallowing it.
3. **Trustee export hides failures** (`src/pages/FinancesPage.tsx`): per-invoice PDF generation is wrapped in an empty catch, so an export that silently omits invoices still reports success. Count the failures and warn with the count, the way skipped receipts already do.
4. **Missing indexes** (`src/db/index.ts`): add `time_entries(project_id)`, `time_entries(date)` and `quotes(client_id)` beside the existing index list.
5. **Resource tags inserted one by one** (`src/db/queries/resources.ts`): batch the tag inserts into a single statement, matching how other multi-row inserts are done.
6. **Untranslated income categories** (`src/pages/IncomePage.tsx`): the edit form renders raw category codes with underscores replaced by spaces, bypassing the translations the row badge uses. Render both through the same translation lookup.
7. **State set after unmount** (`src/pages/ResourcesPage.tsx`): the tag-loading effect has no abort, so a slow load resolves into an unmounted component. Guard it the way the codebase's other async effects are guarded.

## 5. Part C — File splits (pure moves)

No logic changes. Each extracted piece keeps its current implementation verbatim; only its file changes. Imports are updated at the call sites.

- **`src/components/ProjectDetailContent.tsx`** (997 lines) splits into its already-isolated pieces: `ProjectTasksSection`, `ProjectResources`, `ProjectWikiBlock`, `ProjectNamedTables`, `SortableSubtaskRow` and `PriorityBadge` each move to their own file under `src/components/project/`. The main component stays, importing them.
- **`src/pages/SettingsPage.tsx`** (1712 lines): the five self-contained managers move to `src/components/settings/`: `SuppliersManager`, `ExpenseCategoryManager`, `CustomListsManager`, `TimeEntriesManager`, and the pickers (`AccentColorPicker`, `ColorSwatchPicker`, `SupplierGroupCard`). The shared `SettingRow`, `SettingsCard` and `SectionHeader` helpers move to one file the new components import.
- **`src/components/NamedTable.tsx`** (602 lines): the cell renderer becomes `TableCell` and the column-editor popover becomes its own component, both in `src/components/named-table/`. This one is a decomposition rather than a move, so it carries the most care: behaviour must be identical, and the existing Enter-to-save test must keep passing.

## 6. Part D — Shared extraction

### 6.1 Receipt preview and attachment

`ReceiptPreview` is duplicated near-verbatim in `ExpensesPage` and `IncomePage`, and both carry the same `attachReceipt` file-picker, sanitise, copy and update flow. Both move to shared modules, with the only real difference (a background class) passed as a prop.

### 6.2 Shared PDF document

`InvoicePDF` (499 lines) and `QuotePDF` (429 lines) share their entire stylesheet and almost all of their layout. The shared parts move to `src/components/pdf/`:

- `documentStyles.ts` — one `createDocumentStyles(template)` producing the stylesheet both documents use.
- `PdfDocumentLayout.tsx` — the shared body: header with business and client blocks, meta rows, the line-item table with its dynamic column order and global-rate collapsing, notes, totals with the VAT-exempt note and discount row, the bank-details block, the thank-you line and the page number.

`InvoicePDF` and `QuotePDF` become thin components that compute their own differences and pass them in: the title and draft label with its existing casing per kind, the meta rows including the invoice's purchase-order row, the amount formatter (currency-aware for invoices, Swiss francs for quotes), the footer block (payment terms for invoices, validity for quotes), the reminder banner, and the QR bill. The QR bill stays invoice-only and keeps its own module.

**The binding constraint:** the two stylesheets must be diffed key by key before anything is shared. Any key whose value genuinely differs between the two documents stays a parameter. Values are never harmonised to each other, because that would silently change one of the two documents.

## 7. Testing

- **Golden PDF snapshots, taken before the refactor.** A new test renders `InvoicePDF` and `QuotePDF` with fixed fixtures against mocked react-pdf primitives that record their element type and style props, and snapshots the resulting tree. The snapshots are committed while the components are still untouched, then must be unchanged by the extraction. This is the safety net for section 6.2 and the reason it can be done at all.
- Each Part A page gets a test for the navigation contract: Down moves the focus, Enter opens the focused row, collapsed groups are skipped on Tasks.
- Each Part B fix gets a test that fails before it: a second submit while pending creates nothing, a save scheduled for one article does not write to another, a failed invoice PDF is counted and reported, the income edit form shows translated categories.
- Part C is covered by the existing suite plus a render test per extracted component where none exists. A pure move that changes no behaviour is verified by the suite staying green, not by new assertions.
- Gates unchanged: `npx vitest run`, `npx tsc --noEmit`, `npm run lint`, `cargo test`, `cargo clippy`, and the design-system greps.

## 8. Risks

- **A changed invoice.** Mitigated by the golden snapshots and the no-harmonising rule. If the two stylesheets turn out to differ anywhere meaningful, that key stays parametrised.
- **A behavioural slip in the Settings or project splits.** These files have thin coverage, so the moves must be verbatim; any temptation to tidy while moving is out of scope.
- **NamedTable decomposition** is the one piece that rewrites rather than moves. If it cannot be done without behaviour drift, it is dropped from the release rather than rushed.
